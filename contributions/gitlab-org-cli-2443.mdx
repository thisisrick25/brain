## What was done
- Implemented a new `glab cluster agent token-cache` command group.
- Added `glab cluster agent token-cache list` to display cached agent tokens from keyring and filesystem caches.
- Added `glab cluster agent token-cache clear` to remove cached tokens, with an option for automatic revocation on the GitLab server.
- Both `list` and `clear` commands support filtering by agent IDs and specifying cache sources (`--keyring`, `--filesystem`).

## Impact
- Users gain visibility and control over previously opaque cached GitLab Agent tokens.
- Provides a direct way to manage credentials used by the Kubernetes credential plugin.
- No breaking changes were introduced.

## Technical details
- The new commands manage cached agent tokens stored in both keyring and filesystem caches.
- The `clear` command integrates with the GitLab server for token revocation, defaulting to `true`.
