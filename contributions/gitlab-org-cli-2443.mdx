## What was done
- Implemented a new `glab cluster agent token-cache` command group.
- Added `glab cluster agent token-cache list` to display cached agent tokens from keyring and filesystem caches, with filtering options.
- Added `glab cluster agent token-cache clear` to remove cached agent tokens, including optional revocation on the GitLab server.
- Both new commands support filtering by agent IDs (`--agent`) and specifying cache sources (`--keyring`, `--filesystem`).

## Impact
- Users can now manage and view GitLab Agent tokens previously stored in a "black box" cache.
- Provides greater control and transparency over credentials used by the Kubernetes credential plugin.
- No breaking changes were introduced.

## Technical details
- New commands interact with both keyring and filesystem to manage cached agent tokens.
- Includes logic to communicate with the GitLab server for optional token revocation when clearing the cache.
