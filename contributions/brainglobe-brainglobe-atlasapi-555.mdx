## What was done
- Removed `orientation` and `transformation_mat` parameters from the `generate_metadata_dict` function.
- Eliminated the `"orientation"` and `"trasform_to_bg"` keys from the metadata dictionary generated during atlas packaging.
- Updated the `METADATA_TEMPLATE` to no longer include an `orientation` field.
- Removed all orientation transformation logic (for stacks and meshes) and `transformation_mat` calculation from `wrapup_atlas_from_data`.
- The `Atlas` class's `orientation` property now explicitly returns `descriptors.ATLAS_ORIENTATION` ("asr"), and `AnatomicalSpace` is initialized with this constant, instead of reading from metadata.

## Impact
- **Atlas Packagers:** Input data (reference stacks, segmentations, meshes) for new atlases *must now be provided in the 'asr' orientation*. The atlas generation process will no longer perform automatic reorientation.
- **Atlas Users:** All atlases loaded via `brainglobe-atlasapi` will consistently adhere to the "asr" orientation, simplifying coordinate system understanding and removing the need to consult metadata for orientation details.
- **Codebase:** Simplifies the atlas generation and loading logic by removing redundant orientation transformation steps and metadata fields.

## Technical details
- Refactored `brainglobe_atlasapi/atlas_generation/metadata_utils.py` and `brainglobe_atlasapi/atlas_generation/wrapup.py` to remove parameters and logic related to dynamic orientation.
- Modified `brainglobe_atlasapi/descriptors.py` to update the metadata template.
- Updated `brainglobe_atlasapi/core.py` to enforce `descriptors.ATLAS_ORIENTATION` as the fixed orientation for the `Atlas` object and its internal `AnatomicalSpace`.
