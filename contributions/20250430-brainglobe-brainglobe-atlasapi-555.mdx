## What was done
- Removed `transformation_mat` and `orientation` parameters from `generate_metadata_dict`.
- Eliminated the `orientation` and `trasform_to_bg` keys from the atlas metadata generated by `generate_metadata_dict`.
- Removed the internal logic within `wrapup_atlas_from_data` for calculating and applying orientation transformations (e.g., `map_stack_to`, `map_points_to`).
- Discontinued the use of `brainglobe_space` for coordinate transformations during atlas packaging.
- Refactored the `Atlas` class to directly use the `ATLAS_ORIENTATION` constant ("asr") for its origin and orientation properties, rather than inferring from metadata.
- Updated the metadata template to no longer include an "orientation" field.

## Impact
- **For developers generating atlases:** Input data (stacks, meshes) must now be provided directly in the "asr" anatomical orientation; the API no longer handles re-orientation during packaging.
- **For users of atlases:** Atlases are consistently assumed and verified to be in the "asr" orientation, simplifying usage and reducing potential orientation-related errors.
- Simplifies the atlas metadata structure by removing redundant orientation transformation matrices.

## Technical details
- Changes span `metadata_utils.py`, `wrapup.py`, `core.py`, and `descriptors.py`.
- The `brainglobe_space` dependency for runtime orientation handling during atlas generation has been removed.
- The `ATLAS_ORIENTATION` constant (defined as "asr") is now the single source of truth for atlas orientation within the `Atlas` class.
