## What was done
- Migrated the `project.license` field in `pyproject.toml` from a dictionary to a direct SPDX-compliant string (`"Apache-2.0"`).
- Added `license-files = ["LICENSE"]` directly under the `[project]` section and removed its redundant entry from `[tool.setuptools]`.
- Updated the `setuptools` build-system requirement from `>=61` to `>=77.0.3`.
- Removed the redundant `"License :: OSI Approved :: Apache Software License"` classifier from `pyproject.toml`.

## Impact
- No functional changes to the Falcon framework.
- Improves compliance with modern Python packaging standards (PEP 621) and tool interoperability through SPDX license expressions.
- Ensures consistency and accuracy of project metadata for downstream consumers and tooling.

## Technical details
- Modifications were made exclusively to `pyproject.toml`, aligning the project metadata with current best practices for Python packaging.
- The change to `project.license` reflects a move towards using concise SPDX license identifiers.
- The `setuptools` version bump reflects an update to the project's build dependencies.
