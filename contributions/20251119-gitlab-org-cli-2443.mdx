## What was done
- Implemented the new `glab cluster agent token-cache` command group.
- Added `glab cluster agent token-cache list` to display cached agent tokens from keyring and filesystem, with filtering options.
- Added `glab cluster agent token-cache clear` to remove cached agent tokens, including an option to revoke them on the GitLab server.
- Both `list` and `clear` commands support `--agent` for filtering by agent IDs, and `--keyring`/`--filesystem` to specify cache sources.
- The `clear` command's revocation is enabled by default via the `--revoke` flag.

## Impact
- Users can now inspect and manage previously opaque cached GitLab Agent tokens used by the Kubernetes credential plugin.
- Enhanced control and visibility over cached credentials improves user experience and security management.
- No breaking changes were introduced.

## Technical details
- The new commands interact with both keyring and filesystem caches for token storage.
- The `clear` command integrates with the GitLab server for token revocation, providing a complete management lifecycle.
